Human–Agent Collaborative Community

Hikmah

群贤
一个让人类成员与专业 Agent 在清楚的身份、规则、上下文、审批和审计边界内共同工作的私有团队社区。
3–20 人私有团队 AgentScope 协调 QwenPaw 专家 显式意图优先 个人 Agent 私密隔离
Executive Summary

设计结论

Hikmah 把“社区身份与治理”“协作协调”“专业 Agent 工作”分成三个稳定边界。

Hikmah 产品层

拥有团队、频道、线程、角色、专家席位、规则、审批、知识和审计。

AgentScope 协调层

运行团队与频道轻量 Sidecar，负责克制路由和多 Agent 协作，不给出专业结论。

QwenPaw 专家层

实现服务端共享专家及成员本机 Personal Agent，拥有 Workspace、Skills 和工具环境。

命名约束：产品英文名为 Hikmah，中文名为群贤，仓库名为 hikmah。其他实体只使用功能名称，不设置独立文化品牌。
显式 @

直达指定专家，Channel Sidecar 仅观察。

未显式 @

规则优先，最多选择一名主答专家。

副作用

独立 Policy / Approval Service 控制。

跨频道知识

只有人审晋升这一条路径。

Approved Architecture

总体方案 · 控制面 + Agent 网关

AgentScope 负责协作秩序，QwenPaw 负责专业工作；Hikmah 保持产品领域权威。

选择理由

职责边界最稳定，可同时容纳共享专家和成员本机 Personal Agent。

未选择：QwenPaw 中心化

会把个人 Agent OS 与团队社区领域缠在一起。

未选择：完全中立核心

首版会重复建设 AgentScope 已提供的大量协调能力。

Design 01

系统边界与代码所有权

hikmah 是唯一产品代码仓库；两个上游运行时不成为产品仓库中的隐式分支。

hikmah · 产品领域唯一所有者
Community Web / API
Collaboration Domain
Coordination Adapter
Agent Gateway / AgentLink
Policy / Approval
Knowledge Promotion / Audit
不 vendor 上游源码 不 monkey patch 不直连上游数据库 不维护长期 fork
AgentScope

公开 SDK / Service；协调 Sidecar 与 Team / Invite / MessageBus 运行语义。

QwenPaw

公开 ACP / API / Plugin；共享专家和 Personal Agent 运行时。

代码所有权

所有者拥有内容
Hikmah社交领域数据、RBAC、频道规则、TaskRun、审批、Agent 映射、团队知识和审计。
AgentScope协调 Agent 会话与运行状态、Team / Pipeline / MessageBus 语义。
QwenPawWorkspace、Skills、Plugins、专业记忆和本地工具环境。
上游修改唯一通道：识别通用扩展点 → 最小上游 PR → 等待正式发布 → Hikmah 固定版本 → Adapter 启用。产品不依赖未合并的长期补丁。
Design 02

领域模型、身份与权限

MVP 只有一个邀请制 Team Space；三类 Agent 身份彼此隔离。

Human
Team Owner最终治理权限
Admin成员、Channel、Expert Seat 与策略配置
Member发言、@、发起任务、授权范围内审批
Personal Agent Binding绑定唯一 Member；可连接本机 QwenPaw
Collaboration Space
Team Space成员、专家名册、全局规则、团队知识与审计边界
Team Coordinator Sidecar轻量、默认静默、只处理团队级协调
Channel长期主题、成员可见性、专家与频道记忆
Channel Coordinator Sidecar未 @时按需路由；处理秩序与治理
Thread / TaskRun具体讨论、执行、审批、结果与知识候选
Temporary Group Chat显式成员列表；默认无协调 Sidecar
Shared Expert
Expert Seat团队拥有的稳定社交身份
↓
Agent Runtime Bindingendpoint、runtime、capabilities、version、presence
↓
Server-side QwenPaw专业 Workspace、Skills、Plugins、工具环境
Channel Expert Membership逐项授权 @、路由、补充、上下文与工具能力
Personal Agent 不是共享成员

仅 Owner 调用；选择性上下文；私密输出；Owner 确认后才能分享。

Coordinator 不是专业专家

无专业结论、无业务工具权限，只处理协调和治理。

按能力授权

读取、回复、检索、提议工具、副作用执行和审批分别授权。

术语说明：Personal Agent 的 Owner 指绑定该 Agent 的 Member，不等同于 Team Owner 治理角色；Team Owner 与 Admin 也不能查看其私有正文。
Design 03

消息路由与协作任务流

显式选择永远优先于智能路由，两条路径严格分离。

路径 A · 明确 @专家

1
验证发言者与 Expert Seat 的 Channel 权限。
2
Agent Gateway 直接投递给指定 QwenPaw。
3
被 @的多位专家分别独立响应。
4
Channel Sidecar 只观察和审计，不路由、不总结、不调停。
5
副作用仍由独立 Policy / Approval Service 控制。

路径 B · 未明确 @

1
规则优先执行协作意图门控；闲聊默认不触发。
2
选择一名主答专家；歧义时才使用轻量模型。
3
创建 TaskRun 并投递主答 QwenPaw。
4
主答按需邀请补充专家，并统一整合结果。
5
方案 → 审批 → 执行 → 结果 → 知识候选。

TaskRun 状态机

OPEN→ROUTED→WORKING→AWAITING_APPROVAL→EXECUTING→COMPLETED/FAILED/CANCELLED
可介入：无人响应

超过阈值后提醒或改派一次，不循环催促。

可介入：竞争或冲突

指定主答，要求补充者转入 Thread，由主答整合。

可介入：治理事件

审批、硬规则、定时总结和 Knowledge Candidate。

永不介入：Sidecar 不得给出专业结论，不得在明确 @路径中组织对话，也不得替人类批准副作用。
Design 04

记忆、隐私与执行治理

记忆按作用域隔离，知识只能经人审晋升；审批绑定精确执行计划。

记忆边界

Thread / Channel Memory普通对话与阶段结论留在原 Channel。
Expert Stable Memory身份、能力、技能版本和安全约束由 Admin 管理。
Team Knowledge只包含已审阅、带来源和版本的知识对象。
Personal Agent MemoryOwner-only，长期记忆默认留在成员本机。

唯一跨频道路径

知识候选→人类审阅→定范围 / 脱敏→发布→版本化 / 撤回
硬规则：模型不能把聊天自动升级为 Team Knowledge；总结不等于发布。

执行决策

自动执行
只读检索、分析、草稿和无副作用计算；仍需审计。

默认拒绝
越权、目标含糊、参数漂移、凭据缺失或策略冲突。

谁提出
Expert Seat + Member
做什么

Personal Agent 隐私路径

Owner 选择上下文→最小 ContextEnvelope→本机 QwenPaw→Owner-only 结果→Owner 主动分享
Design 05

运行拓扑、可靠性与 MVP

共享协作运行在团队服务器；Personal Agent 由成员本地托管并主动出站连接。

私有团队服务器

Hikmah Web / API领域、ACL、TaskRun、知识与审计
AgentScope Coordination Runtime两级轻量 Sidecar 与专家协作
Agent Gateway + Policy能力、上下文、协议、审批和执行记录
Shared QwenPaw Pool按 Expert Seat 隔离 Workspace 与能力
认证出站连接
短期令牌
最小上下文

成员设备

Personal QwenPaw成员自行运行、升级和配置
AgentLink Client不开放本机入站端口
Owner-only Session私密结果；分享必须由 Owner 明确执行
上游边界：只使用 AgentScope 与 QwenPaw 公开接口，通过 Adapter 隔离版本差异；确需修改时只提交可复用的最小上游 PR。
失效与降级
  • 显式目标离线时不擅自换专家
  • Sidecar 故障时显式 @仍直达
  • 仅幂等只读操作有限重试
  • 副作用状态不明进入人工核验
  • Policy / Audit 故障时写操作 fail closed
验证体系
  • RBAC、路由和状态机单元测试
  • 固定上游版本的 Adapter 契约测试
  • @直达、路由、邀请、审批和知识集成测试
  • 跨 Channel、Owner Scope、治理角色泄漏、重放和注入安全测试
  • 离线、取消、部分失败和审计端到端测试
MVP 闭环
  • 3–20 人邀请制 Team Space
  • 共享 Expert Seat + Personal Agent
  • 显式直达 + 克制单主答路由
  • 只读自动 + 副作用审批
  • 人审 Knowledge Promotion
Delivery Strategy

MVP 交付切片

完整 MVP 不使用一份巨型计划一次性交付；每个切片都形成可验证的端到端能力。

Slice 1

私有 Team Space、Channel、Thread、Expert Seat、服务端 QwenPaw、明确 @直达与基础审计。

Slice 2

两级 Sidecar、未 @路由、单主答、TaskRun 和专家邀请。

Slice 3

能力授权、Policy / Approval、Execution Card 与受控执行。

Slice 4

Personal Agent Binding、AgentLink、Owner-only 结果和主动分享。

Slice 5

Knowledge Promotion、版本与撤回、全面安全和可靠性加固。

下一步边界：正式规范获复核后，只为 Slice 1 编写 implementation plan，不提前实施后续切片。
