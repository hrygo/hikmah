Executive Summary

产品灵魂不变，基础设施收缩

GitHub 调研推翻的是早期自建实现，不是已经批准的人机协作行为。Hikmah 从“新社区全栈”收敛为“成熟 Foundation 上的轻量治理层”。

完整修订等待用户正式复核
3–20邀请制私有团队成员
3 类Shared Expert / Personal Agent / Sidecar
0明确 @专家时 Sidecar 介入次数
1未 @时最多一名主答专家

本轮撤销的重复建设

Community Web / API

Team、Channel、Thread、DM、消息、搜索、文件、通知和基础 RBAC 交给协作 Foundation。

Agent Gateway / AgentLink

改用 Foundation 原生 Bot/Event API 与 QwenPaw Channel / Plugin；本机 Agent 主动连入 Owner 私聊。

Policy / TaskRun / 基础设施

权限、审批、会话、计划任务、记忆和观测复用 AgentScope/QwenPaw；只保留关联薄层。

Hikmah 只专注五件事：专家身份绑定、Sidecar 行为规则、Personal Agent 隔离、Knowledge Promotion、跨系统 Correlation。
GitHub Landscape

广泛调研后的 Foundation 候选

排序是 Spike 顺序，不是已经拍板的生产选型。许可证、品牌、隐私、核心补丁和兼容升级均是一票否决项。

Mattermost · 技术首选
QwenPaw 原生 Channel成熟协作许可/品牌门禁

Channel、Thread、DM、文件、搜索、RBAC、Bot/Plugin API 完整。只有确认目标发行方式与商标规则后才可 Adopt。

Zulip · 首要备选
Apache-2.0Topic 线程需 Channel Plugin

许可路径清晰；Bot/Event API 成熟。QwenPaw 的公开 register_channel 足以在 Hikmah 仓库完成薄适配。

Open WebUI Channels · AI 原生对照
人 + AI 同线定制许可证身份待证

交互最接近 AI 社区；但三类 Agent、外部 QwenPaw、Personal Agent 隔离和长期品牌约束都必须实测。

CircleChat · 功能参照
目标最相似早期项目维护集中

值得借鉴 Context Packet、Action allowlist、审批和 Agent Runtime；当前成熟度与高权限部署面不足以作稳定底座。

调研不是一次性名单

门禁必须回答
功能能否用公开扩展点完成核心旅程，不改核心、不双写数据？
法律许可证、商标、品牌、分发方式和未来规模是否可接受？
维护发布是否活跃、维护是否过度集中、升级和退出是否可重复？
安全插件、Bot、工具、容器和本地 Agent 是否可收敛到最小权限？
成本Adopt / Integrate / Borrow 是否确实不足，为什么必须 Build-gap？
Stars 不是答案：本轮同时扫描了聊天社区、AI 工作台、Agent 编排、协议、身份授权、审批、记忆、观测、评测和持久工作流等数十个 GitHub 项目；具体清单与证据见研究报告。

最小产品对象

ExpertSeatBinding

稳定社交身份 ↔ Foundation Bot ↔ 固定 QwenPaw Workspace。

SidecarRuleProfile

作用域、显式 @抑制、意图门控、主答选择和有限干预。

PersonalAgentBinding

唯一 Member、私聊身份、运行时、撤销和分享规则。

PolicyBinding

能力和风险规则到权威运行时策略的引用，不做第二次裁决。

KnowledgeCandidate

来源、候选内容、范围、敏感级别与人工审阅状态。

CorrelationRecord

消息、会话、工具、审批和 Trace 的外部 ID；不复制正文。

Identity Model

三类 Agent 身份严格分离

谁拥有、谁能调用、能看到什么、能否发共享消息，都由 Foundation ACL 和运行时权限共同证明。

Shared Expert
Expert Seat团队拥有的稳定名称、头像、专长与职责
Foundation Bot按 Channel 授权 @、回复与上下文
Server QwenPaw独立 Workspace、Skills、Memory 与工具
Coordinator Sidecar
Team Sidecar全局身份、低频治理、默认静默
Channel Sidecar未 @时路由；明确 @只观察
No professional tools不提供专业结论，不替人类批准
Personal Agent
唯一 Member 绑定此 Owner 不是 Team Owner 角色
Owner-only 私聊不是共享 Channel 成员，其他人不可 @
Local QwenPaw记忆留本机；选择上下文；本人确认后分享
不是 UI 隐藏：若 Foundation 无法在 ACL 层证明 Personal Agent 不能读取共享内容，候选直接淘汰，不能靠应用过滤补救。
Routing & Coordination

显式选择优先，智能协调克制

消息沿 Foundation 原生 Bot/Event 通道流动；不再经过自建 Agent Gateway。

路径 A · 明确 @专家

1
Foundation 验证 Member、Channel 和 Expert Bot 权限。
2
事件直接进入被 @专家的 QwenPaw Channel。
3
专家在原 Thread 独立回复；离线时原样失败。
4
Channel Sidecar 确定性进入 observe-only。
5
副作用由专家运行时原生权限/HITL 处理。
0 次介入：不重路由、不改写、不总结、不调停、不邀请。

路径 B · 未明确 @

1
Sidecar 规则先做协作意图门控；闲聊不触发。
2
按专长和可用性选择一名主答；歧义才用轻量模型。
3
通过 Foundation 原生 @唤醒主答 QwenPaw。
4
主答可在 Thread 邀请补充专家，并整合结论。
5
只读自动；副作用审批；结果可成为知识候选。
最多一名主答：避免多 Expert 争抢、循环 @与资源放大。

Correlation 不是新工作流

Foundation Thread→Sidecar Session→QwenPaw Session→Tool / Approval→OTel Trace

Hikmah 只关联外部 ID 和最后已知状态；实际执行状态由运行时拥有。状态不明时显示“待核验”，不自动重放。

Memory, Knowledge & Approval

记忆按域保存，知识只能人审晋升

四个权威作用域

Thread / Channel 对话

由 Foundation 保存，默认不跨 Channel。

Expert Stable Memory

由 QwenPaw ReMe 或 AgentScope 的现成适配保存。

Team Knowledge

只包含已审阅、带来源、范围、版本和状态的对象。

Personal Agent Memory

留在成员本机，不上传、不注入 Shared Expert。

执行由权威运行时裁决

自动
只读、分析、草稿、无副作用计算；仍留运行记录。
审批或精确预授权
写文件、发消息、变更任务和外部业务系统操作。
默认拒绝
越权、含糊、参数漂移、凭据缺失、策略冲突或审批不可用。
Execution Card 是投影：展示 AgentScope/QwenPaw 原生 tool proposal、参数、影响、diff、有效期和 proposal id，不建立第二套审批引擎。

唯一跨 Channel 路径

Knowledge Candidate→人类审阅→定范围 / 脱敏→发布→版本化 / 撤回
硬规则：模型不能自动发布 Team Knowledge；总结不等于发布；没有人类确认时内容留在原作用域。

最小权限

Shared Expert、Personal Agent 与两级 Sidecar 使用不同身份和凭据；Agent 不继承创建者权限。

不可信扩展

Bot、Plugin、Webhook、MCP、文件、URL 和模型输出都必须校验；禁止无边界主机权限。

失败关闭

审批/权限不可用时拒绝副作用；未知状态转人工核验，不能自动重试。

高权限红线：不向应用或 Agent 暴露 Docker Socket、宿主根目录、共享管理员凭据或未收敛的任意代码执行权限。
Delivery Strategy

先选底座，再交付产品切片

每个 Slice 都重复执行 GitHub 复用门禁；没有证据时，不引入新的基础设施。

Slice 0

Foundation Reuse Spike：四候选同场测试，完成许可、品牌、隐私、运维和兼容升级门禁，输出 Accepted 选型 ADR。

Slice 1

已选 Foundation + Expert Seat Binding + 一个服务端 QwenPaw Expert + 明确 @直达 + 基础 Correlation。

Slice 2

AgentScope 两级 Sidecar、显式 @零介入、未 @单主答、有限专家邀请与失败可见。

Slice 3

本机 Personal QwenPaw owner-only、最小上下文、明确分享、Policy Binding 与审批投影。

Slice 4

Knowledge Promotion、版本撤回、安全回归、可观测性、备份恢复、依赖许可/SBOM 与升级门禁。

下一步边界：本修订稿获复核后，只为 Slice 0 编写实施计划；不得跳过 Foundation 选型直接建设应用。
