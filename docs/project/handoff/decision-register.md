# Hikmah 关键技术决策交接簿

本簿保留离任时最重要的判断链，而不是替未来实验填写成功结论。D-01～D-08 当前均为 `open`；继任技术负责人接管技术证据，产品负责人接管范围与价值判断。每项结果写入新的有日期验证记录，按[记录协议](records-and-acceptance.md)关联工作项、AR/CR 和 ADR。

## D-01：公开准入扩展能否真正故障拒绝

**解锁对象：** P0-02.A/B/C、P0-06.C；AR-010、CR-012。责任：技术负责人。

**已知：** [源码研究](../../research/2026-09-05-knowledge-collaboration-feasibility.md)定位 QwenPaw `v2.2.0-beta.1` 的 `PluginApi.register_runtime_hook`、`PRE_DISPATCH` 和 `HookAction.SHORT_CIRCUIT`；不能由这些符号存在推导未注册/卸载后仍受保护。

**接手操作：**

1. 核对公开 release 的完整 commit、插件注册签名和适用入口；输出实际注册插件、实例数、Workspace 和生命周期清单。
2. 在获准隔离环境装入最小 probe，模型/工具替身只记录启动次数，Foundation 使用合成 Post；保留独立观察点，不能只读 Hook 自己的“拒绝”日志。
3. 分别测试冷启动未注册、运行中卸载、重载窗口、新 Workspace、校验异常/超时、命令、Console、后台入口、Channel 入口；每种故障前后都送一个精确人类提及。正常对照组必须确实执行，否则“全部 0 次”可能只是实验没接通。
4. 禁止路径中模型/工具启动必须为 0；Hook 前已经读到的上下文单列给 D-02。记录短路后的 Post/用户状态，不能把拒绝显示成完成。

**通过动作：** 冻结已证实的注册/停用及部署契约，供 P0-06 复用；在所有实际开放入口都受保护后解锁后续。**失败动作：** 保持相关能力关闭，提出上游公开扩展改进或新的窄适配 ADR；readiness 探针、稍后杀进程、私有 monkey patch 不能替代执行点保证。

## D-02：读取隔离与最小上下文是否成立

**解锁对象：** P0-03.B、P0-07.C、P1-02.C；AR-009。责任：技术负责人/操作者。

**已知：** Hook 位于 Channel 获取上下文之后；共享 Workspace、session 或容器名称不天然等于权限边界。试点每席位单 Channel，独立记忆、索引、文件、凭据和受限执行环境。

**验证协议：** 建 A/B 两个合成 Channel，在 B 的历史、文件、自动记忆和索引分别放不同标记；A 中直接问、提示注入、代码引用、跨 Thread 引用均不应读到 B 标记。观测实际上下文请求、工具读取和模型输入，不只查最终回答。再移除成员或收窄 Bot 权限，用旧 session 续问，确保已缓存上下文不能绕过新权限。凭据和工具不能具有超出席位 Channel 的隐含能力。

**通过动作：** 输出信任域、ACL、挂载/网络、工具白名单及撤销过程，加入部署资格。**失败动作：** 停用相关席位，收窄 ACL/上下文或重建隔离环境再测；不能扩大知识发布范围掩盖原始对话泄漏。任何真实资料前完成该门禁。

## D-03：知识撤回与最终发送的公开控制点

**解锁对象：** P1-03.B/C/D；AR-011。责任：技术负责人及评审人。

**已确定：** 权威知识版本在 PostgreSQL；索引为投影；检索与发送前都校验请求者/受众、来源处理权和当前发布状态。首批知识回答发送前缓冲，未通过逐段授权验证的流式输出关闭。

**验证协议：** 在检索完成、模型生成中、发送前、外部请求开始后四个 barrier 分别撤回/缩窄 scope；同时测试旧缓存、旧 session、自动记忆、恢复旧备份和重建索引。前三个 barrier 的受影响结果不应产生新 Post；第四种必须记录已在途竞态并停止后续发送，不能伪称已披露内容收回。缺 usage 清单或权限状态未知时停止相关输出，必要时重建空白受控上下文。

**先行资格：** 固定 QwenPaw 公开的实际发送控制入口、是否先于任何流式字节、是否覆盖附件/错误回帖/重试；PRE_DISPATCH 本身不能充当最终发送拦截的证据。

**通过动作：** 冻结 guard 和撤回传播契约，写明竞态边界并由负责人接受实际开放范围。**失败动作：** 知识回答保持关闭，先解决公开扩展或改变经批准的交付切片；不新增私有 Gateway，不只清向量索引就放行。

## D-04：固定版本、Plugin 宿主和交付许可

**解锁对象：** P0-03.A/C、P0-07.A；AR-007。责任：技术负责人，涉及法律/分发判断由有资格负责人复核。

**事实源：** [版本基线](../../architecture/version-baseline.md)。上游参考仓库更新不自动改变本次资格目标，必须记录实际 release tag、完整 commit、镜像 digest 与锁文件。不得为了绕过失败降低 React/TS/Python 目标或侵入上游。

**验证协议：** 在目标版本分别验证 API Python 依赖、隔离的 QwenPaw/AgentScope 运行环境、React 19.2 与 Mattermost 公开 Plugin API、单 bundle 安装/禁用/卸载/升级。导出实际 BOM/SBOM；核验拟用和分发方式的许可/品牌、责任人及适用范围。不要把 README 的版本范围或容器 tag 当解析制品证据。

**通过动作：** 使用唯一被验证组合推进。**失败动作：** 记录具体冲突组件/接口及影响，提版本基线/ADR 修订；不私有注入第二套宿主组件，不把进程隔离等同许可证结论。

## D-05：数据生命周期、误连保护和恢复

**解锁对象：** P0-01.C/D、P0-04.A/B/C；AR-006。责任：技术负责人/操作者。

**当前问题：** 导入 config 构造全局 Settings，Base 构造 Engine，测试复用 Engine 并清表。P0-01 的完整卡已明确这三条风险，不允许只传 `_env_file=None` 就宣称无导入读取。

**验证协议：** 先完成独立测试保护与显式 app/fixture 接线，再证明 `.env` 和环境变量污染下 sentinel 的 schema/行不变；之后 PostgreSQL 用独立 database/role、Alembic revision 检查和数据库唯一约束实现幂等。并发/崩溃/恢复后相同事件不重复保留。备份恢复必须在新隔离库校验 schema、行、外键、幂等键及实际读用；不覆盖在线库。

**通过动作：** P0-04 替换 P0-01 中尚未开放的生产迁移资格限制，记录实际恢复点与耗时。**失败动作：** 保持生产/真实数据关闭；已有原型 SQLite 数据先盘点和备份，再提出数据迁移任务，不能 `drop_all` 后宣布升级成功。

## D-06：可信 Actor、服务身份与个人边界

**解锁对象：** P0-05.A/B/C、P0-06.A，后续 PA-D；AR-002。责任：技术负责人。

**已确定：** 身份来自服务端 Mattermost OAuth/BFF session；帖子、模型字段、请求 body 中的 user/role/reviewer 不能赋权。Shared、Personal、Sidecar 和内部服务分开身份。托管 owner-only 不承诺防基础设施管理员读取。

**验证协议：** 固定实际 OAuth 库与公开登录/回调契约，覆盖 state、适用的 PKCE、CSRF、session 固定/过期/撤销、成员移除、源权限和目标受众；内部服务认证绑定 runtime 与席位，不能只凭 post_id/correlation。分别证明 401、403、隐匿资源的 404、409 及依赖故障拒绝，错误/日志无 Token 或私密正文。

**通过动作：** 冻结公开 API 与客户端类型，接入所有受保护路由。**失败动作：** 保持相关 API 不开放，不将 UI 隐藏当授权。PA 阶段先确定本机出站/托管连接与分享快照，独立评审后才做个人连接。

## D-07：实际专家入口的自动协作预算

**解锁对象：** P2-02.A/B/C、P2-03；AR-010。责任：技术负责人。

**已确定：** 无 @自动协作以原始人类事件为根，最多一主两辅、一层邀请；显式人类多专家不被此预算改写，显式目标不自动扩邀。Sidecar 只做协调，不能给专业结论或替人审批。

**验证协议：** 先证明公开邀请路径能在发邀请 Post 前登记根事件/目标/邀请者，目标 Hook 能反查并原子消费；帖子里的 correlation 不足以授权。再以并发 20 次、重复/乱序、新 Post ID、进程重启、补充者递归、超时未知和迟到事件检查参与者与外部 Post。停止 Sidecar 时合法明确 @仍可工作；停止准入时所有新 Agent 执行拒绝。

**通过动作：** 冻结 AgentScope 窄适配/预算事务及固定版本 E2E。**失败动作：** 自动路由/邀请关闭，保留经过独立门禁的显式知识协作；不能把限额放在 Sidecar 内存或靠模型提示语控制。

## D-08：真实业务价值与高级能力投入

**解锁对象：** P1-04.A/B/C、M3 PA/EX、RQ。责任：产品负责人，技术负责人提供成本/可行性证据。

**验证协议：** 开始前固定至少 30 个获授权真实任务、资料范围、两类任务分布、评分 rubric、模型/BOM、目标受众、成本上限和原流程对照。记录全部尝试、失败/重试成本、引用存在/版本/支持断言/受众四项及人工返工；采纳为 0 时每采纳成本不可计算。敏感明细留在受控环境。

**决策：** 按实际质量、返工、成本及运维负担决定继续、缩小、扩大；不以安全失败交换业务分数。PA/EX 先独立确定连接/工具与威胁模型，未知外部执行结果不自动重试。完整 MVP 必须通过 PRD 全旅程与量化 NFR，不能直接沿用局部试点报告。

**失败动作：** 选择一个主要失败类型做受控改进实验，保留完整样本，不无限增加 Agent、共享记忆或通用基础设施。没有技术/产品负责人承担判断时，团队先解决责任和能力缺口。
